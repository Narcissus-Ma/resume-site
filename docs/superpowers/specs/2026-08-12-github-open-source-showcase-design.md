# GitHub 开源作品展示设计

## 背景

项目是一套 React + TypeScript 实现的多语言个人主页与简历站点，包含公开展示页面和可选的 Cloudflare Worker 管理后端。当前仓库缺少根级开源说明、贡献与安全反馈规范，且 Worker 文档保留了个人生产域名和 KV 标识，不适合原样公开到 GitHub。

本次开源的主目标是展示个人的产品完成度与工程实践，并让中文开发者可快速理解、运行和部署；同时为国际访问者提供足够的英文入口和核心说明。

## 目标

- 建立中文优先、英文可用的 GitHub 首屏说明，清楚表达项目用途、能力和运行方式。
- 向潜在访客展示前端、多语言、主题、内容管理与可选 Worker 后端等工程亮点。
- 给出可执行的发布前检查与两周推广节奏，降低首次发布成本。
- 增加贡献、安全与 Issue/PR 协作边界，令仓库具备基本的公共协作条件。
- 移除仓库文档中的个人生产基础设施标识；保留通用部署指引。

## 非目标

- 不修改应用功能、接口行为或生产环境配置。
- 不替用户创建 GitHub 仓库、推送代码或发布任何公开内容。
- 不承诺维护大型社区，也不增加复杂的自动化工作流。

## 信息架构

### 根级 README

使用中文标题、中文正文为主，并在相邻位置提供简洁英文对照。内容按读者决策顺序组织：

1. 项目定位和在线演示占位符。
2. 截图/GIF 占位符与核心亮点。
3. 技术栈与目录结构。
4. 前端快速启动、环境变量和常用命令。
5. 前端静态部署与可选 Cloudflare Worker 后端部署入口。
6. 自定义内容、国际化和主题的文档入口。
7. 贡献、安全、许可证和推广文档链接。

README 不写入个人姓名、真实 API 域名、KV Namespace ID、Token、密钥或备份数据。发布前由仓库所有者将 README 的 `DEMO_URL` 占位符替换为真实的公开演示地址；在尚未部署演示时，保留“暂未提供公开演示”的明确文字，不展示无效链接。

### 协作文档

- `CONTRIBUTING.md`：中文流程为主体，配英文摘要；定义 Issue 搜索、最小复现、分支和提交建议、质量检查、PR 描述和敏感信息禁止项。
- `SECURITY.md`：列出不得提交的敏感信息、私下反馈漏洞的方式及处理范围。仓库所有者可在发布前替换联系邮箱或 GitHub 用户名占位符。
- `.github/ISSUE_TEMPLATE/bug_report.yml`、`.github/ISSUE_TEMPLATE/feature_request.yml`：引导反馈提供版本、复现与预期，减少无效 Issue。
- `.github/pull_request_template.md`：要求填写改动说明、验证命令和关联 Issue。
- `LICENSE`：采用 MIT，便于个人作品的学习、复用和展示。

### 推广文档

`docs/open-source-promotion.md` 用中文提供：

- 发布前仓库检查表（脱敏、许可证、演示、截图、GitHub Topics、仓库简介、社交预览图）。
- 首发当日的 GitHub 发布动作与可直接改写的中文/英文简介。
- 面向掘金、知乎、微信公众号/个人博客、即刻或朋友圈的内容角度和文案骨架。
- 发布后两周节奏：首发、技术拆解、功能演示、迭代/复盘，并以收藏、Star、Issue 质量、演示访问和部署反馈作为观察指标。

## 脱敏策略

对外文档范围包括根目录 README、`CONTRIBUTING.md`、`SECURITY.md`、`cloudflare/README.md`、`docs/` 下非历史记录的发布文档，以及 GitHub 模板。实施前先对仓库的 Markdown 文档全文搜索个人生产域名和 KV 标识；按当前扫描结果，只有 `cloudflare/README.md` 需要移除真实资源。其“当前生产资源”段落将改为通用示例，不出现真实 Worker 名称、个人域名、真实 KV ID 或允许来源。配置示例统一用 `api.example.com`、`your-worker-name` 与中文占位符表达。

应用运行时的默认 API 地址、`wrangler.jsonc` 中的生产绑定和历史设计/计划文档属于既有部署与历史记录，本次不修改；README 会说明开源使用者应通过 `VITE_RESUME_API_BASE_URL` 配置自己的地址。发布前检查表将明确要求仓库所有者在公开前再次审查这些非文档配置，按实际部署决定是否进一步迁移或替换。

## 推广策略

主叙事聚焦“从可展示到可运营的个人主页”：不是单页静态简历，而是具备双内容形态（主页/简历）、三语、多主题、在线管理能力和可选无服务器后端的完整作品。

渠道优先级：GitHub 仓库与 README 是唯一事实来源；掘金发布工程拆解以获取中文技术受众；个人博客或知乎阐述设计决策；社交平台使用截图/短视频引导至 GitHub。英文传播以 GitHub About、英文 README 摘要与英文 Release 说明为主，避免维护多平台的长篇翻译。

## 验收标准

- 新访客能在 README 首屏了解项目定位、技术栈、启动方式，以及有效演示链接或明确的演示可用性状态。
- 经全文搜索，对外文档范围中不再出现当前个人生产域名、KV Namespace ID 或敏感凭据；非文档配置和历史记录作为发布前人工复核项被明确标注。
- 贡献者可根据 `CONTRIBUTING.md` 完成开发、检查和 PR 提交。
- 反馈者可通过 Issue 模板报告问题或建议，安全问题有明确的非公开反馈路径。
- 推广文档包含发布前检查、首发内容和至少两周的后续节奏。
- 新增 Markdown/YAML 文件可通过格式检查；现有应用构建不受文档改动影响。
